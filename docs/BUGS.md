# GreenDream Comprehensive Bug & Audit Registry (BUGS.md)

| ID | Screen / Component | Symptom | Verified Root Cause | Severity | Status | Resolution |
|:---|:---|:---|:---|:---|:---|:---|
| **BUG-01** | Global / `Navigation.tsx` / `App.tsx` | Bottom content & rightmost buttons overlapped/hidden by Nav & floating "+" FAB | `BottomNavigation` (height 62px + 10px inset) and FAB (`bottom: 84px`, `end-5`) float fixed over viewport. | **BUG-02** | `AssistantScreen.tsx` | Message "Copy" button unreachable and invisible on touch devices | Row action button uses `opacity-0 group-hover:opacity-100`. | **BUG-03** | `AssistantScreen.tsx` | Input box & Send button covered by on-screen keyboard | Chat input row is in normal scroll flow with `pb-28` rather than sticky/pinned above the keyboard. | **BUG-04** | Global / Multi-modal sheets (`AddActionSheet`, `FinanceScreen`, `GymScreen`) | Form submit buttons obscured by soft keyboard on small screens (360x640) | Modals use fixed centering or bottom positioning without keyboard-aware scroll container or viewport shrink listener (`window.visualViewport` / native resize), pushing primary submit buttons below viewport edge when keyboard deploys. | **P0** | **RESOLVED** | Enabled Android adjustResize native layout shrink and converted modal form content to scrollable viewport containers with safe-area padding. |
| **BUG-05** | Global / Multi-layer UI | Inconsistent z-index scale causing overlay collisions | Nav bar and FAB are `z-40`, sticky header on Dashboard is also `z-40`, modals and sheets use arbitrary `z-50`, `z-60` or `z-[60]`. No unified token scale (`content < sticky header < nav < FAB < sheet scrim < sheet < dialog < toast`). | **P1** | **RESOLVED** | Standardized 8-tier semantic z-index scale (`--z-content: 1`, `--z-sticky-header: 20`, `--z-nav: 30`, `--z-fab: 35`, `--z-sheet-scrim: 40`, `--z-sheet: 50`, `--z-dialog: 60`, `--z-toast: 70`). |
| **BUG-06** | `storage.ts` / `DEFAULT_AI_SETTINGS` | AI request failure on Android APK when custom/default backend is invoked | Default `backend_url` was set to `http://localhost:3001`. On an Android device or emulator, `localhost` resolves to `127.0.0.1` on the phone itself where no backend service exists (`ERR_CONNECTION_REFUSED`). | **P0** | **RESOLVED** | Removed default localhost URL; enabled direct Gemini client mode (`direct_mode: true`, `backend_url: ''`) with automatic migration of legacy localhost settings. |
| **BUG-07** | `capacitor.config.json` | WebView CORS and cleartext HTTP block network requests | `CapacitorHttp` plugin was not enabled in `capacitor.config.json`. Standard WebView `fetch()` enforces strict CORS against `https://localhost` origin and Android 9+ blocks cleartext HTTP. | **P0** | **RESOLVED** | Enabled `CapacitorHttp: { enabled: true }` in `capacitor.config.json` and added `android:usesCleartextTraffic="true"` to `AndroidManifest.xml`. |
| **BUG-08** | `geminiService.ts` / `AssistantScreen.tsx` | Requests fail silently or report cryptic errors without actionable recovery | Network/quota errors lacked structured user-facing guidance (e.g. distinguishing 401 invalid key, 429 quota exhaustion, 503 high demand, and offline network state) with dedicated retry button and setup fallback card. | **P1** | **RESOLVED** | Added 3-tier fallback candidate chain (`gemini-3.6-flash` -> `gemini-3.5-flash` -> `gemini-3.1-flash-lite`), sanitized history payloads to eliminate empty text parts, added 35s timeout and actionable error cards. |
| **BUG-09** | `storage.ts` (`getSeedData`) | Fresh install is cluttered with mock/demo records from 2026 | First launch initializes `getSeedData()` with 5 habits, dummy transactions (180,000 DA salary, cafes, groceries), gym workout plans, tasks, journal entries, and mock loans with 2026 timestamps instead of a clean empty state. | **P0** | **RESOLVED** | Created `getCleanInitialState()` with 0 demo transactions, 0 tasks, 0 loans, 0 habits. On first launch, app starts completely clean; existing users retain all data with backward-compatible migration. |
| **BUG-10** | Global / Architecture | No first-launch onboarding or setup wizard | Fresh installs lack a personalized setup flow (`settings.onboarded`). Users cannot choose their name, language, active modules, initial budget, or appearance before entering the app. | **P0** | **RESOLVED** | Built `OnboardingModal.tsx`: 5-step interactive wizard (Welcome & Language, Modular selection, Baseline numbers, Look & Feel, Done) with preset buttons ("Complete Life", "Essentials", "Minimalist"). |
| **BUG-11** | Global / Architecture | Disabled modules cannot be toggled off | `settings.modules` is absent from schema. Users cannot deactivate modules they do not need (e.g. users who do not want gym, prayer, or loans). | **BUG-12** | `DashboardScreen.tsx` / `MoreScreen.tsx` | 360px viewport text truncation & layout shift on large font scales (130%) | Metric labels and button text lack responsive scaling or wrap control, causing numbers and text chips to truncate or overflow horizontal boundaries at 360px width. | **P2** | **RESOLVED** | Added adaptive flex-wrap, dynamic grid column counts (`grid-cols-${tiles.length}`), and minimum 44px touch targets. |
| **BUG-13** | `speechService.ts` / `HermesChatModal.tsx` | Speech recognition terminates prematurely or throws unhandled error on Android APK | 1) `SpeechRecognition.start({ partialResults: true })` resolves immediately in native Java (`call.resolve()`) as startup handshake; wrapper treated resolution as completion, killing listener in 0ms. 2) Native `SpeechRecognition.java` suppresses `onError` when `call` is resolved, so JS never receives error codes. 3) Bare ISO code `'ar'` causes Samsung/Xiaomi recognizers to fail with `ERROR_CLIENT` (code 5) instead of requiring regional BCP-47 (`ar-SA`, `ar-DZ`). 4) Web Speech API is absent in Android WebView. | **P0** | **RESOLVED** | Built `src/services/voice/SpeechInput.ts` with continuous partial result handling, dynamic BCP-47 tag resolution (`ar-SA`, `fr-FR`, `en-US`), silence auto-stop timer (~1.3s), permanent denial detection, and native `popup: true` dialog fallback. | **BUG-14** | `HermesChatModal.tsx` | Permanent microphone permission denial leads to a dead-end UI | When a user taps "Don't allow" or "Never ask again", `requestPermissions()` returns `denied`. | **BUG-15** | Global Audio / Voice Assistant | Audio focus conflicts and echo loops during speech | No centralized audio session manager coordinates microphone listening vs TTS playback. | **BUG-17** | `HermesChatModal.tsx` | Voice recording in chat was not captured as an audio message | Composer microphone button only performed transient speech-to-text recognition without preserving the raw audio recording, rendering audio playback bubbles impossible and failing multimodal Gemini audio understanding. | **P1** | **RESOLVED** | Built `VoiceMessageService.ts` capturing AAC/WebM audio, attached `HermesVoiceAttachment` to user messages, created interactive `VoiceMessagePlayer.tsx` with 24-bar scrubbable waveform and 1x/1.5x/2x speed selector, and serialized audio as Gemini `inlineData`. | **BUG-18** | `SpeechOutput.ts` | High latency before Hermes begins speaking long text replies | Text-to-speech previously waited for the entire LLM response stream to complete before invoking Android TTS, causing an 8–10s silence delay. | **P1** | **RESOLVED** | Implemented sentence boundary streaming queue (`queueChunk`) in `SpeechOutput.ts`.
